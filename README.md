# 活版実験室

Next.js / Reactの画面とRust / WebAssemblyの印刷エンジン。ブラウザ内で文字・画像から単色用の版を作り、インクを塗って紙へ転写します。

## 解像度

- シミュレーションの紙：**8192 × 8192 / 4096 × 4096**を選択できます（初期値8K）。インク転移、紙の接触、にじみ、飛沫、湿ったインクの移動、圧痕をこの格子で処理します。
- PNG保存：**4096 × 4096**。8Kでは格子の2 × 2点を、色へ変換した後で平均します。4Kでは対応する計算セルをそのまま保存します。プレビューを拡大して保存する処理ではありません。
- 画面プレビュー：640 × 640。版のプレビュー・手塗りの膜厚と顔料のフィールド：512 × 512。手塗りを8Kの版上で双線形補間します。
- 合成した凸版の二値マスク：8K時6552 × 6552、4K時3272 × 3272。画像は各版の原稿として長辺2048pxまで読み込み、組版サイズに合わせて網点・二値化を計算します。

紙は64 × 64のタイルに分割し、インクや圧痕が発生したタイルだけ確保します。紙の湿った顔料・乾いた層の反射率・湿潤／乾燥膜厚は16ビットで保存し、512 × 512の連続した紙の高さ場を生成し、計算格子へ補間します。密な全面印刷では紙の状態だけで8Kで約1.21 GB、4Kで約0.302 GB、画像入力・出力・ブラウザのキャンバスにも追加メモリが必要です。8K処理はWeb Worker上で行いますが、処理時間や必要メモリは画像と端末に依存します。

解像度は最初の画面で選びます。「実験を始める」を押すまでエンジンは読み込みません。途中で変更する場合は「版・紙をリセットして最初に戻る」を選びます。印刷途中での自動切り替えはありません。

## ローカル起動

```cmd
pnpm install --frozen-lockfile
pnpm dev
```

コンパイル済みWASMとWorkerを同梱しています。Next.jsの依存関係はpnpm-lock.yamlに固定されています。

## Rustを変更する

rustupから最新のstableをインストールします。rust/rust-toolchain.tomlでもstableを選択しています。

```cmd
rustup update stable
rustup target add wasm32-unknown-unknown
pnpm build:wasm
pnpm test:wasm
pnpm dev
```

Windows上の標準MSVC構成で通常のcargo testを実行するには、Visual StudioのC++ビルドツールとWindows SDKが必要です。このエンジンのWASMだけをビルドし、Node.jsでWASMをテストする場合はそれらを必要としません。エンジンに外部クレートやC/C++ビルドスクリプトはありません。

```cmd
cargo test --manifest-path rust/Cargo.toml
pnpm exec eslint .
pnpm exec tsc --noEmit
pnpm build
```

## テスト

- rust/src/lib.rs：15件。圧力ゼロ、転移量の上限、ローラーの有限量・インク保存・拭き取り・停止中の非塗布、紙の接触・空押し・方向に応じた糸引き、4K/8K出力と透過、乾燥・紙の交換を検査します。計算規則の単体テストは小さな格子で実行します。
- scripts/test-wasm.mjs：実際の4096/8192格子のWASM、疎なタイル確保、透過4K出力、転移、乾燥、ローラーとWorkerのメッセージ転送・進捗、組版の衝突判定、AM網点の面積階調と誤差拡散を検査します。全8K面を厚塗りする負荷テストではありません。
- GitHub Actions：Rustテスト、WASMビルド／テスト、ESLint、Next.jsビルドを行ってoutをPagesへ公開します。

## モデルの範囲

カラー画像は輝度またはRGB成分を単色用の網点・二値版に変換します。原画像の色を自動で多版印刷する機能はありません。塗った色は版の膜厚とともに保持され、印刷で減少します。

接触・分離・インク輸送は物理現象を参考にした簡略モデルです。色はRGBから推定した吸収／散乱係数を使うKubelka–Munk層モデルの近似です。実測した分光顔料モデルではありません。縁のはみ出しは版の境界に沿って移動し、紙へのにじみと稀な飛沫には再現可能な乱数を使います。実測の粘度・圧力・紙物性による実機結果の予測には使えません。

参考文献：[Studies on Printing Ink Transfer (1986)](https://www.jstage.jst.go.jp/article/nig1958/24/1/24_1_41/_article/-char/en)


## 文献を踏まえた転移量の改訂

接触面積率、有限の紙側受容量、残余膜の分裂を分けて扱います。

- 1986年の転移実験（J-STAGE要旨確認）は、圧力・膜厚による被覆率の変化と、膜厚・速度による分裂率の変化を報告しています。
- 1991年の転移パラメータ推定研究（J-STAGE要旨確認）は、被覆面積も測定して係数を推定する必要性と、元の固定化関数の限界、Weibull型関数への改訂を述べています。
- 今回はWeibull型の被覆／受容曲線、有限の受容量、膜厚・速度による残余膜の分裂率を使う現象論的近似です。論文の実測係数の再現や1991年の式の忠実な実装ではありません。受容量の紙粗さ・粘度への対応も仮の係数です。転移量をゼロ以上・塗布量以下に制限します。
- 2020年の液橋論文（arXiv本文確認）は、PAA水溶液で濡れ性と粘弾性が分配を大きく変えることを示します。油性の活版インクに同じ数値を移せる根拠はありません。現行の剥離方向・飛沫は依然簡略表現で、この論文の流体計算を実装したものではありません。

紙表面の高さ場と圧縮による接触、剥離方向と粘弾性に連動する糸引きは、今回、簡略モデルを実装しました。今後は実測に基づく紙物性、表面インクと内部に浸透する溶媒／顔料の分離、液橋の流体計算、顔料の分光的な重ね色を改善する必要があります。とくに紙上の柄に合わせてランダム汚れを足すだけでは、これらを再現できません。実物の刷りで被覆率・濃度・輪郭の広がりを測って調整する必要があります。

追加文献：
- [A Modified Method for the Determination of the Ink Transfer Parameters by Non-linear Optimization (1991)](https://www.jstage.jst.go.jp/article/jtappij1955/45/7/45_7_809/_article/-char/en)
- [Viscoelastic Liquid Bridge Breakup and Liquid Transfer Between two Surfaces (2020)](https://arxiv.org/abs/2001.10209)


## 背景透過PNG

「結果を保存する」の「PNGの背景」で「透過（インクだけ）」を選ぶと、4K RGBA PNGにインク層の色と不透明度だけを出力します。紙目・圧痕は出力せず、インクのないセルはalpha=0、薄いインク・にじみは半透明になります。8K→4Kは色をalphaで重み付けしてから平均し、縁に紙色が混ざるのを防ぎます。RGBAは白背景上でモデルのインク透過率を再現する近似であり、任意の背景上での実際の印刷色を保証するものではありません。RGBの吸収・散乱近似により白色インクも出力できますが、実測した顔料の隠蔽力ではありません。


## 組版と塗布

作業は「解像度 → 基本的な組み方 → 文字を入れる → 画像を入れる → ローラーと色 → 塗布 → 刷る → 保存」です。画面の用語は「版」に統一し、その中に文字・画像の「台座」を配置します。

- 1つの版には画像を1枚、文字を256文字まで配置できます。画像を再選択すると現在の版の画像だけを置き換えます。文字は1文字ずつ独立した台座です。文字どうしは台座の境界を接して置けます。画像が関わる台座間は2単位の間隔を確保します。台座はドラッグ・矢印キーで移動でき、角のハンドルでサイズ変更できます。重なりや版面外への配置は拒否します。
- 写真は45度のAM網点（細かさ32〜192）または誤差拡散、画像の線画は二値化を選べます。入力文字は常に二値版で、画像用の設定には影響されません。AMは点の面積と写真の階調を対応させ、暗部の点がつながっても階調が連続する円／正方形セルの面積関数を使います。階調の調整は写真用gamma、しきい値は二値版だけに作用します。網点・誤差拡散は最大96%の面積率に抑えます。
- 組版や製版設定を変更すると版の塗布インクを拭きます。印刷済みの紙は保持します。
- 手塗りは、幅を持つローラーの移動線上で、凸部とローラーのインク膜を交換します。停止中に点を加算する方式ではありません。ローラーは有限のインク量を持ち、同じ色は残った量で続け、別の色や設定に変えると次の塗布前に補充します。明示的な補充ボタンもあります。版からインクを回収するとローラーの色に混ざります。
- 「紙のインクを乾かしてから次を刷る」を刷る前に選びます。乾燥は紙上の前の印刷に作用し、これから刷るインクは湿ったままです。

## 接触・圧痕・剥離の改訂

- 連続した高さ場の紙を、圧力と接触時間で圧縮し、局所的な隙間とインク膜の厚みから接触率を求めます。紙の外観も同じ高さ場から作ります。インクなしでも版を押した部分には圧痕ができます。
- 粘度と糸引き（粘弾性）を別の操作にしました。剥離方向を向いた版の縁では、転移量の一部を方向に沿う細い筋へ配分します。長さ・量は速度、膜厚、糸引きに依存します。転移量の残りを減らして筋に配分し、架空のインクは追加しません。ただし16ビット量子化・飽和の誤差はあります。
- 圧縮の対数依存と接触時間の扱いは1989年の紙の粗さ・圧縮性研究、粘度と伸長弾性の区別は2020年の液橋研究を参考にしたものです。既存論文の条件はニュースプリントや水系高分子液等であり、油性活版インクと手押し条件の実測係数として流用していません。高さ場・接触式・筋の配分は、実測未校正の現象論的モデルです。液橋のNavier–Stokes/FENE-P計算や本物の飛沫軌道計算は実装していません。

追加文献（本文の理論・説明・考察を確認）：
- [杉崎誠：印刷における階調表現 (2005)](https://www.jstage.jst.go.jp/article/photogrst1964/68/4/68_4_309/_article)
- [Mangin & Geoffroy: Printing Roughness and Compressibility (1989)](https://bioresources.cnr.ncsu.edu/wp-content/uploads/2020/02/1989.2.951.pdf)

## 組版・文字・重ね刷り

「版を作る」「インクを塗る」「刷る」を独立した640pxの画面に分けました。版作成画面で画像と文字の台座を組み、スナップ（なし／4／8／16／32）と位置・大きさの固定を使えます。角からのサイズ変更と幅変更はスナップに合わせます。画像は縦横比保持を選べ、文字は常に保持します。固定した版はドラッグ・矢印キー・幅変更で動きません。重なり・版面外への配置は禁止します。

入力した文字は改行に対応し、端末の明朝体、Google FontsのNoto Serif JP／Noto Sans JP／Zen Old Mincho／Shippori Minchoを選べます。入力文字は二値版です。Google Fonts CSS2 APIへ入力文字のサブセットを要求して実際にフォントが読み込まれてから画像化します。読み込み失敗時はエラーを表示し、選択書体を黙って代替しません。通信なしでは端末の明朝体を選んでください。文字は1文字ずつ画像に変換し、追加後も文字ごとの書体と上下左右の余白を変更できます。余白を変更すると台座の幅・高さも変わります。文字の内容を変える場合はその文字を外して追加します。

湿ったインクは膜厚と吸収量を加算し、同じセルでは混合した一つの層として反射を計算します。乾燥すると反射率を下層へ固定し、その後の湿ったインクを新しい層として重ねます。乾いた層の顔料は移動・再混合しません。透明な層は下の色の影響を受けます。乾燥による単純な色変化はなく、次の刷りの混合・重なり方が変わります。乾いた多層をRGB反射率に圧縮して保持するため、完全な分光多層モデルではありません。湿潤混合はセル内で均一とする近似で、実際の濡れた油性インクが必ず完全混合するという意味ではありません。

参考：Curtis et al., [Computer-Generated Watercolor (SIGGRAPH 1997)](https://grail.cs.washington.edu/wp-content/uploads/2015/08/curtis-1997-cgw.pdf)。吸収・散乱による混合と順序を持つ層の重ね合わせを参考にしています。水彩の流体モデルを活版インクへそのまま適用したものではありません。

転写膜厚を紙側の湿潤／乾燥フィールドに保持します。厚みは紙と版の接触間隙を埋め、次の刷りの接触に影響し、局所的な傾斜を陰影に使います。「インクの盛り上がりの陰影」は表示上の陰影強度です。高さは相対量で、実測μmや乾燥収縮ではありません。湿った膜の移動は膜厚と顔料を一緒に移し、乾いた膜は保存します。高厚膜の保存上限は合計約16相対単位です。

透過4K PNGは引き続き既定です。白いインクも透過画像に残ります。RGBAは白背景での光学結果に合わせた近似で、任意の背景色で分光透過を再現するものではありません。紙の凹凸・圧痕・厚膜の陰影は「紙を含める」で保存します。

## 複数の版と参照表示

「使う版」で最大8枚を切り替えます。「新しい版を作る」は紙を交換せず、空の版を追加します。各版は組版、選択中の台座、インク膜厚と顔料を独立して保持し、切り替えだけならインクを載せ直す必要はありません。組版・書体・余白・画像設定を編集した版は、その版の塗布インクだけを拭きます。紙の印刷・乾燥・圧痕は版を切り替えても残ります。ローラー自体は共通です。

「透かして参照する版」で他の版を複数選べます。濃さを調整して、組版画面で鏡像の位置を合わせます。この青い参照表示は印刷エンジンやPNG出力には入りません。参照版は組版座標で表示し、印刷時の紙へのオフセットは表示に含めません。版・文字・塗布状態の保存は現在のブラウザセッション内です。ページを再読み込みするとリセットされます。

文字の台座は字面を正方形の文字枠内に配置し、枠の外側に指定した上下左右の余白を追加します。文字ごとのドラッグ・サイズ変更・固定・書体変更に対応し、異なる書体を同じ版に混在させられます。改行は次の行を作り、空白はインクのない台座になります。文字追加は1回128文字までです。禁則処理・OpenTypeの字詰め・縦組み・リガチャは実装していません。

ローラーだけをUIに残しました。ローラー枠は独立したDOM表示にして、版面の画像更新とは分離しています。小さな移動はまとめ、軸の向きを180度周期で補間し、往復やホバーで表示が反転・リセットしないようにしています。塗布イベントはフレーム単位でまとめてWorkerへ送り、版の切り替えや印刷の前に未処理の塗布を完了させます。実際の有限膜の交換モデルは引き続きRustで計算します。

追加検証：WASMテストで各版の塗布状態保存／復帰を実物のバイト配列で比較し、文字台座の隣接・重なり、余白による台座サイズ、角の反対側の固定とサイズスナップ、ローラーの180度反転を確認します。ブラウザでも1文字の余白・異なる書体・画像差し替え・角操作・版の切り替え・複数参照・重ね刷り・透過4K保存・モバイル表示を確認しています。
